## Cross-cutting schema capabilities

- A Task Property Definition is shared by every Task in one Task Collection; each Task owns an independent value.
- Filtering, sorting, searching, and grouping are available for every datatype unless explicitly excluded; silence is not an exclusion ([DEC-080](decisions.md#dec-080--query-and-grouping-capabilities-are-available-by-default)).
- Every Task Property Definition may be marked Mandatory. Enabling it does not backfill existing Empty values; the next submitted edit form for an affected Task requires all Mandatory values to be non-empty ([DEC-081](decisions.md#dec-081--every-task-property-may-be-mandatory)).
- Text-like queries use Task Collection locale collation, case-insensitive and diacritic-sensitive comparison, Empty in negative filters, and Empty last in both sort directions ([DEC-082](decisions.md#dec-082--text-like-queries-share-comparison-and-empty-rules)).
- Property names are trimmed, non-empty, and case-insensitively unique within the schema. Every duplicable datatype uses `Name Copy`, then `Name Copy 2`, `Name Copy 3`, and so on; ID is non-duplicable ([DEC-079](decisions.md#dec-079--property-naming-and-duplicate-suffixes-are-shared)).
- Multiple definitions of the same datatype are the default; ID is a singleton exception.
- Generic creation initializes Empty. Exceptions: Checkbox initializes `false`; existing Status values are Empty but new Tasks receive Default; system-derived properties project existing Task facts; ID activation backfills immutable numbers.
- Generic removal deletes the definition and exposed values after an always-required confirmation showing the `Is not empty` count. The count and effect include every retained Task without active/archive/soft-delete, visibility, or current-view filtering ([DEC-101](decisions.md#dec-101--deletion-impact-includes-every-retained-task-without-lifecycle-filtering)). ID deletion additionally removes its prefix, all assignments, and sequence counter; re-addition creates a fresh sequence from `1` ([DEC-087](decisions.md#dec-087--id-property-deletion-permanently-removes-its-state)).
- ID deletion confirmation counts every retained assignment, including soft-deleted Tasks ([DEC-086](decisions.md#dec-086--id-deletion-impact-includes-soft-deleted-tasks)).
- Successful Task archive/restore updates both Last edited time and Last edited by atomically; removing/re-adding either definition does not reset its retained Task fact ([DEC-088](decisions.md#dec-088--archive-and-restore-update-both-last-edit-facts)).
- Generic duplication creates an independent definition, copies configuration, and asks whether to copy values. Exceptions: Text uses confirmation and copies definition configuration only; Date Range always copies; Checkbox no-copy initializes `false`; Created time, Created by, Last edited time, and Last edited by project the same system fact without prompting; ID cannot be duplicated.
- Every accepted Task Property change writes audit and domain metadata evidence to the existing Core tables indefinitely. There is no product read surface, raw value payload, reconstruction guarantee, or separate datatype history store ([DEC-078](decisions.md#dec-078--audit-and-domain-logs-are-the-shared-version-record), [DEC-102](decisions.md#dec-102--task-property-logs-are-indefinite-internal-metadata-evidence)).
- Created time and Last edited time obtain the effective viewer zone from Core Principal Preferences: configured value, then browser initialization/fallback, then `UTC` ([DEC-095](decisions.md#dec-095--core-principal-preferences-owns-the-configured-iana-time-zone)).
- Person, Created by, and Last edited by use the durable Core Principal contract for eligible-person search, historical resolution, Actor identity, Originating Principal propagation, and named System attribution ([DEC-038](decisions.md#dec-038--person-directory-separates-eligible-search-from-historical-resolution), [DEC-062](decisions.md#dec-062--created-by-is-intrinsic-immutable-task-provenance), [DEC-071](decisions.md#dec-071--last-edited-by-attributes-automation-to-origin-or-system)).
- Select automatic option order uses each viewer's configured user locale; switching to Manual snapshots the acting user's displayed order ([DEC-096](decisions.md#dec-096--select-automatic-option-ordering-uses-the-viewers-user-locale)).
- Empty Select values match `is not <option>`; explicit empty predicates continue to govern presence ([DEC-097](decisions.md#dec-097--empty-select-values-match-is-not-option)).
- Select, Multi-select, and Status use the existing `ColorSelect` component for authorized Option color choice/editing. This engineering decision adds no palette, serialization, or automatic-selection business rule ([DEC-098](decisions.md#dec-098--option-color-editing-uses-colorselect)).
- Core References may target any registered Business Entity across microverticals and tenants; providers govern discovery and authorize immediately before opening ([DEC-099](decisions.md#dec-099--core-references-span-microverticals-and-authorize-when-opened)).
- Stale editable-value writes are rejected without merge or overwrite, show a Toast, and preserve the user's unsaved draft ([DEC-100](decisions.md#dec-100--stale-task-property-value-writes-are-rejected-with-the-draft-preserved)).
- Property and option deletion counts and effects include all retained archived and soft-deleted Tasks without lifecycle or view filtering ([DEC-101](decisions.md#dec-101--deletion-impact-includes-every-retained-task-without-lifecycle-filtering)).
- Core Media rejects positive type mismatches, accepts unknown content as generic download-only, exposes no preview, and authoritatively enforces deployment-wide `CORE_MEDIA_MAX_UPLOAD_BYTES` with a 100 MiB default ([DEC-103](decisions.md#dec-103--core-media-authoritatively-validates-download-only-uploads)).
- Every operation made available only by the default-capability rule now has concrete datatype-aware search, filter, sort, and grouping semantics ([DEC-104](decisions.md#dec-104--default-enabled-query-operations-use-datatype-aware-semantics)).
