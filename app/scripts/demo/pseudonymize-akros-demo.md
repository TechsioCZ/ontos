# Pseudonymous demo company: stage operator runbook

`pseudonymize-akros-demo.mts` moves the demo tenant's screw seller (company `…0024`) to its pseudonym
**Šroubárna Vysočina s.r.o.** with the brand **ŠroubShop**. The storefront runs on `https://ontos-stage-shop.web-revolution.cz`
(Zerops service `shop`). Deployment never runs this operator. Every step is plan → reviewed apply → verify.
Apply requires the exact plan file, its SHA-256 fingerprint, the same deployed composition and an unchanged live state.

| Phase     | Writes (governed Actions only)                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prepare` | `core.identity.configure-demo-companies` (exact legacy guard: demo tenant, `…0024`, CZ, active, `AKROS (demo)`, `DEMO-AKROS` → `DEMO-SROUBARNA`). Stage service principal `sroubshop-storefront` with the exact storefront role. Storefront application `sroubshop-storefront`. Markets SROUB-CZ, SROUB-SK, SROUB-EU, SROUB-PL (suspended) and SROUB-CZ-B2B as copies with associations, pricing and every offer exception. One managed API key.                                                          |
| `retire`  | In this order: delete the old principal's memberships and direct grants, revoke its key and disable it (the shop already runs on the new key). Then end the legacy storefront associations of live markets, retire the AKROS-\* markets and remove the merchandise pricing of every legacy market, including the retired lifecycle QA markets `AKROS-QA-*`, which have no replacement. Then end the associations still current on those retired QA markets and retire the `akros-storefront` application. |

The operator refuses foreign or extra legacy markets, purposes that still name the old brand, conflicting targets
and any change since the plan. Writes are never retried automatically. After a failure, run `verify` or review a
fresh plan; it resumes from the live state. The new key is written only to
`$ONTOS_STAGE_SECRETS_DIR/sroubshop-storefront-api-key` (mode 600) by `pseudonymize-akros-key.sh` and is never printed.

## Operator machine

The operator runs from a machine on the Zerops VPN, which reaches the stage app container as SSH host `app`. Four
variables name its local files. Each tool stops with a clear message when one it needs is unset:

| Variable                    | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ONTOS_STAGE_REMOTE_RUNNER` | Executable remote runner, called as `$ONTOS_STAGE_REMOTE_RUNNER scripts/demo/<operator>.mts [args…]`. It connects over SSH to `app` with `StrictHostKeyChecking=yes` against `ONTOS_STAGE_KNOWN_HOSTS`. On the stdin of `node --input-type=module -` it sends the operator credentials of `obchod@demo.ontos` (never argv or environment), followed by a small launcher. The launcher runs the **committed** script in `/var/www/app` with the app supervisor and Shell runtime environment. Nothing is printed except the operator's own output. |
| `ONTOS_STAGE_KNOWN_HOSTS`   | Pinned `known_hosts` file for `app`. Every deploy replaces the container and its host key, so re-pin it right after each green deploy (`ssh-keyscan app`). Do it only then, never to silence a mismatch at any other time.                                                                                                                                                                                                                                                                                                                        |
| `ONTOS_STAGE_PLAN_DIR`      | Owner-only local directory for copies of the reviewed plan files.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ONTOS_STAGE_SECRETS_DIR`   | Owner-only local directory (mode 700) that receives the new storefront key.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

Plans are written to the container's `/tmp`, so a deploy deletes them. After each plan, keep a copy:
`scp -o UserKnownHostsFile="$ONTOS_STAGE_KNOWN_HOSTS" app:/tmp/pseudonym-<phase>.json "$ONTOS_STAGE_PLAN_DIR/"`.
If the container was replaced in between, copy it back before apply or verify, or simply review a fresh plan.

## Preconditions

1. The real AKROS tenant has its own snapshot of the source data, and the AKROS host `ontos-stage-akros` has been
   cut over to that tenant and verified. Before that cutover, run plans only. Retirement would otherwise empty the
   AKROS host.
2. The deployed release contains this operator, and the host key is re-pinned after its deploy.

## Ordered steps

`R="$ONTOS_STAGE_REMOTE_RUNNER"`. Run every command from `app/` on the operator machine.

| #   | Step                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Reversible?                                                                                                                                                                                                                                                                           |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `$R scripts/demo/pseudonymize-akros-demo.mts --mode plan --phase prepare --plan /tmp/pseudonym-prepare.json` and review the plan. The output lists the fingerprint, markets, grant counts and whether the key is already active.                                                                                                                                                                                                                      | read-only                                                                                                                                                                                                                                                                             |
| 2   | `sh scripts/demo/pseudonymize-akros-key.sh apply /tmp/pseudonym-prepare.json <fingerprint>` applies `prepare`, verifies it, installs the key file locally and deletes the container copy. If the local fetch failed after a successful apply, run `sh scripts/demo/pseudonymize-akros-key.sh fetch` before the next deploy. If the key is already active, apply with `$R … --mode apply --phase prepare …` without `--issue-key`.                     | The company rename is forward-only (the Action has no reverse path). Principal, grants and key can be undone by disabling the principal, deleting its relationships and revoking the key. Markets can be suspended, but their codes are permanent. Pricing and offers can be removed. |
| 3   | `$R … --mode verify --phase prepare --plan /tmp/pseudonym-prepare.json --reviewed-plan-sha256 <fingerprint>`                                                                                                                                                                                                                                                                                                                                          | read-only                                                                                                                                                                                                                                                                             |
| 4   | Set the Zerops `shop` service variables `ONTOS_AKROS_STOREFRONT_API_KEY` (file contents, never echoed), `ONTOS_STOREFRONT_APP_ID=sroubshop-storefront` and `STOREFRONT_BRAND=sroubshop`, then restart `shop`. The key does NOT belong in `release-bundle.json` / `DEMO_IMMUTABLE_RELEASE_SECRETS`. Those hold owner-unit secrets; storefront keys are storefront service variables.                                                                   | yes (previous variables)                                                                                                                                                                                                                                                              |
| 5   | Push the service slice: `scripts/demo/permissions.mts` (`akrosStorefrontPrincipal` → `sroubshop-storefront`, label) and `scripts/demo/eshop-markets-stage-grants.mts` (`eshopStorefronts` app id). Every deploy runs `reconcile-stage-service-grants.mts --apply`, so this slice must ship only after step 2. It must be green before step 7, or startup would keep reconciling the old principal. Wait for one green deploy and re-pin the host key. | yes (revert commit)                                                                                                                                                                                                                                                                   |
| 6   | Verify the shop host: /cs, /sk, /en, cart and order, and SROUB-PL suspended (noindex). `eshop-markets-stage-grants.mts --mode plan/verify` must pass against the new application.                                                                                                                                                                                                                                                                     | read-only                                                                                                                                                                                                                                                                             |
| 7   | `$R … --mode plan --phase retire --plan /tmp/pseudonym-retire.json`. It refuses until `prepare` is fully verified, the new key is active and the deployed reconciler no longer lists the old principal.                                                                                                                                                                                                                                               | read-only                                                                                                                                                                                                                                                                             |
| 8   | `$R … --mode apply --phase retire --plan /tmp/pseudonym-retire.json --reviewed-plan-sha256 <fingerprint>`                                                                                                                                                                                                                                                                                                                                             | **Point of no return.** Retired markets and the retired application stay retired. The revoked key cannot be restored. Associations, pricing (copied in the prepare plan), grants and principal status could be recreated.                                                             |
| 9   | Repeat `$R … --mode verify --phase retire …` until it passes (owner workers project asynchronously). Never re-apply blindly.                                                                                                                                                                                                                                                                                                                          | read-only                                                                                                                                                                                                                                                                             |

The real AKROS tenant must not use the demo-tenant seeds (`seed-eshop-markets.mts` now seeds the SROUB-\* markets for
`sroubshop-storefront`); it has its own `akros-playground` operators.
