## Outstanding completion dependencies

These limits are still true:

- **Owner ports fail closed in production.** `api/payment-production-layers.ts` wires every downstream owner
  port (C15 term + CCC entitlement, C17 gateway binding, Delivery COD capability, pickup capability, #331
  commitment outcome, refundable items) to its unavailable layer. In production every branch that needs one
  of them answers `UNAVAILABLE_TO_VERIFY` or refuses; the owner behavior above is proven only through the
  public-contract fixtures in `tests/support/*`.
- **Permission is a scripted gate.** Every Action and Read test decides Principal Permission with the scripted
  Core test gate (`allowed` / `denied`), not with SpiceDB or the native permission harness.
- **C17 #1159 provider conformance is outstanding.** Every gateway result above (collection, gateway refund,
  recovery, provider idempotency, account isolation) proves only how Payment handles the declared C17 adapter
  contract, through a fixture. It does not prove GoPay, Stripe or Comgate behavior, provider idempotency
  support or production readiness.
- Composition phase, expiry and fence are varied only in acceptance-composition-fence; every other suite uses the
  Core composition fixture. Phases there are set by the clone's admin connection, except the drain scenario,
  which uses Core's close-admission, drain, seal and Outbox matcher.
- An INDETERMINATE Payment Operation (unknown monetary effect) is Core durable work of `payment.core` under the
  revision of the invocation that made it unknown (custom migration `enforce-payment-ledgers`). While
  it exists Core refuses to drain or seal that release; a proven outcome or governed decision clears it. Business
  waiting (PENDING) and the operation-requested Outbox handoff are not tracked: with no consumer of
  `payment.core.operation-requested.v1` in the composition, Core's matcher records those rows as matched with zero
  deliveries. Integration tests that create INDETERMINATE work publish the matching revision through
  `tests/integration/composition-authority-fixture.ts`, which holds the authority lock Core's native suites share.
- Downstream owners (Storefront, Cart, Delivery, Order, Commitment #331, Fulfillment, Billing, bank/ERP/POS/
  carrier transports) are represented only by named public-contract fixtures. No production journey exists.
